# 果园奇遇项目迭代计划

更新：2026-11-02。按 **1 名开发者、每两周一个迭代** 估算；美术、关卡设计与真机测试若无额外人力，需要相应延长。日期从实际开工日顺延，不把估算当交付承诺。

## 交付目标

**v0.2 可验证规则版（第 1–2 周）**：交换、连锁、障碍命中与血条压力都能给出确定、可回放的结果。

**v0.3 关卡试玩版（第 3–6 周）**：至少 10 个「单一目标 + 周期受伤」手工关卡，完成血条预警、失败重试与新手教学闭环。

**v0.5 内容体验版（第 7–10 周）**：至少 30 个经过试玩调优的关卡、规则游玩集、存档和星级，完成触控与音画打磨。

**v1.0 发布候选（第 11–12 周）**：规则、性能、兼容性和内容通过验收；后续按数据持续迭代。

**v1.x 长期更新（v1.0 之后单独排期）**：遗物构筑、道具库存、每日挑战、更多目标/障碍、可选社交与跨设备进度。每项先做最小版本，再依据真实试玩数据决定扩展。

## 关卡内容节奏

| 关卡段 | 引入内容 | 设计要求 |
| --- | --- | --- |
| 1–3 | 交换、三连、单目标、血条与受伤预告 | 先展示「每 4 次有效行动受伤」的可见倒计数；无复杂障碍 |
| 4–5 | 四连方向动物、五连彩鸟 | 教学局面可复现；用特殊动物加快目标推进，学习减少受伤次数 |
| 6–8 | 冰块、藤蔓 | 分开教学“动物被消除”和“障碍被解除”；藤蔓首次命中保留动物 |
| 9–10 | L/T 爆炸、基础组合、第一种规则变体 | 给出可学习的防护/压迫机制；变体只改变一个参数或反馈 |
| 11–20 | 单一目标类型轮换、棋盘布局和两种变体 | 每 3–4 关新增一个明确变化，保留复习关；同关不堆叠多个新概念 |
| 21–30 | 收集物、复合障碍、精选规则组合 | 用目标达成行动数与受伤次数调难度，避免简单提高伤害 |

前 10 关是首个内容里程碑，30 关是内容管线验收点；不照搬参考游戏的具体关卡布局。

## 血条关卡验收样例

默认测试配置：`maxHealth=5`、`dangerInterval=4`、`damagePerTick=1`、单个目标。连续 3 次有效交换后仍为 5 HP；第 4 次结算后若目标未完成则变为 4 HP。若第 4 次交换的连锁完成目标，则先胜利，仍为 5 HP。无效交换、自动洗牌与连锁均不推进受伤倒计数。若当前 1 HP，下一次应受伤且目标仍未完成，才判失败。护盾先吸收伤害，治疗不得超过最大血量。

规则变体与遗物接口的完整契约见 [规则游玩集](GAMEPLAY_RULESET.md)。

## 每个迭代的固定流程

1. 从 [用户故事](USER_STORIES.md)选入容量可承受的条目，写清规则样例和验收条件。
2. 先完成规则/关卡数据与自动回归，再接 Cocos 表现和音效。
3. 用固定种子录制关键局面；在编辑器和至少一台触控设备上试玩。
4. 记录失败关卡、误触、无效交换、目标达成行动数、受伤次数、胜利血量和主观反馈；只修改能定位原因的参数。
5. 迭代结束输出版本号、关卡清单、已知问题和下一轮阻塞项。

## 发布门槛与指标

| 类别 | 门槛 |
| --- | --- |
| 规则 | 固定局面、特殊组合和障碍矩阵全部通过；属性测试至少覆盖 10,000 个种子局面，无死循环或棋子丢失 |
| 血条 | 胜利先于伤害；无效交换不推进危险值；血量/护盾上下限正确；同一行动只触发一次周期判定 |
| 关卡 | 每关恰有一个目标、开局有合法移动；教学关有可触发的学习机会；人工试玩至少各 5 次并记录结果 |
| 操作 | 非法交换不计有效行动；藤蔓锁定反馈明确；连锁过程中不接受重复输入 |
| 进度 | 断电/重启后已通关、星级和设置可恢复；坏档有安全回退 |
| 表现 | 目标设备上核心操作保持流畅，动画与结算一致；静音和低运动选项有效 |
| 缺陷 | 无 P0/P1 缺陷；其余问题有复现种子、影响范围与处理计划 |

## 风险与处理

- **规则继续堆在 `GameManager.ts`**：先抽出纯规则和事件序列，再扩新障碍，否则组合数量增长会放大回归成本。
- **随机局面导致偶发 bug 难重现**：所有关卡和本局补充棋子使用可记录的种子，失败报告附种子与操作序列。
- **“可解”不等于“好玩”**：自动校验只挡住无效数据；每关仍需试玩评估目标清晰度、难度和节奏。
- **血条退化为隐形步数上限**：提供清晰受伤预告、护盾/治疗与关卡变体；用试玩验证玩家能主动管理风险，而非只计算可走几步。
- **遗物叠加导致无限循环或永久无敌**：在 S1 定义事件阶段与上限，在 S5 用原型验证；正式遗物上线前覆盖组合测试。
- **资源脚本体积持续膨胀**：资源管线迁移与内容扩展并行，在 S5 前完成，避免每新增图片都扩大 `VisualAssets.ts`。
- **范围失控**：商店、付费、社交和大型限时活动暂不纳入 v1.0；先让单机核心关卡可持续玩。
- **长期系统依赖账号与服务端**：单机版稳定前不预设实时排行榜或云存档的上线时间；需要独立评估运营与维护成本。
