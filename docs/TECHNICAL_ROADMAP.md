# 果园奇遇技术路线图

更新：2026-11-02。项目借鉴成熟三消的棋盘反馈与内容节奏，关卡压力采用本项目的「单一目标 + 血条 + 周期受伤」规则。目标是形成可扩展的原创玩法，而非复制参考游戏的美术、文案或关卡数据。

## 参考依据与项目边界

- [乐元素的 App Store 游戏介绍](https://apps.apple.com/cn/app/%E5%BC%80%E5%BF%83%E6%B6%88%E6%B6%88%E4%B9%90/id791532221)明确描述：横竖连接三个及以上同色动物、完成每关指定消除目标、清晰面板与特效、多种关卡类型和障碍。
- [乐元素在 TapTap 的官方页面](https://www.taptap.cn/app/2321)列举收集物、限时挑战、指定物品消除，以及难度逐步上升的关卡。
- [乐元素招股说明书（历史资料）](https://qccdata.qichacha.com/ReportData/PDF/cdc2488b1b9171f92e0474b681e43762.pdf)描述步数内清冰、收集指定动物、道具、持续增加关卡和数据驱动调优。该文件反映历史产品设计，不视为当前版本的完整规则表。

这些来源能确定三消体验方向，不能替代对每个特殊组合和障碍细节的逐项实机验证。血条压力、关卡变体和遗物是本项目主动设计的规则，不宣称属于参考游戏。

## 当前基线

| 模块 | 当前实现 | 与目标体验的主要差距 |
| --- | --- | --- |
| 核心棋盘 | 8×8，五种动物，交换、三消、下落、连锁 | 规则集中在 `GameManager.ts`，难以独立测试和回放 |
| 特殊动物 | 四连方向、五连彩鸟、L/T 爆炸，以及组合效果 | 生成优先级、重叠匹配、障碍吸收和组合矩阵需完整测试 |
| 障碍 | 冰块、藤蔓 | 缺每类障碍的统一“受击层数/是否保留动物/是否阻挡下落”契约 |
| 关卡 | 已有五关单目标样例与血条结算 | 需扩展教学内容、关卡校验、试玩调参和存档 |
| 内容 | 随机棋盘与障碍分布 | 缺关卡配置、编辑与可解性校验 |
| 表现 | 原创动物贴图、程序音效、基础动画 | 缺音频分层、反馈时序规范、移动端适配和性能预算 |
| 进度 | 已显示生命值、受伤倒计数与目标进度 | 缺本地存档、星级和关卡解锁 |
| 关卡外系统 | 暂无地图、道具库存和日常活动 | 缺长期目标；应在核心关卡稳定后建设 |

## 目标架构

```mermaid
flowchart LR
  Input[触控输入] --> Session[GameSession 状态机]
  Level[LevelConfig 关卡配置] --> Session
  Session --> Rules[纯规则引擎]
  Session --> Pressure[HealthPressure 血条压力]
  Rules --> Hooks[规则/遗物效果接口]
  Hooks --> Pressure
  Rules --> Events[ResolutionEvent 事件序列]
  Pressure --> Events
  Events --> View[Cocos 棋盘与 UI 表现]
  Events --> Audio[音频反馈]
  Session --> Save[本地进度]
  Telemetry[匿名本地测试指标] <-- Events
```

### 1. 可测试的规则引擎

把棋盘状态与 Cocos 节点分离。`BoardState` 保存动物、特殊状态、障碍层数和格子类型；`resolveMove(state, move, seed)` 返回新状态与有序事件，且不直接创建节点。随机数由可设定种子提供，保证关卡复现和 bug 回放。

单次行动顺序固定为：输入校验 → 交换 → 匹配分组 → 特殊生成与扩散 → 障碍受击 → 动物消除 → 重力/补充 → 连锁稳定 → 单一目标进度与规则效果 → 胜利判定 → 危险值增加/周期伤害 → 失败判定。非法交换不增加危险值；一次行动中的任意多次连锁只计一次行动。若同一行动达成目标又达到受伤阈值，先胜利且不受伤。每次事件记录受击对象、动物是否保留、目标增量、血量变化和动画顺序。

优先补齐规则表：

| 场景 | 规则契约 |
| --- | --- |
| 3 连 | 消除匹配动物，结算目标与分数 |
| 水平/垂直 4 连 | 在参与匹配的交换落点生成对应方向动物；自然连锁取线中点 |
| 5 连 | 生成彩鸟；`22122 → 22222` 时中心格为彩鸟位置 |
| L/T | 交点或实际交换落点生成爆炸动物；重叠组只结算一次 |
| 藤蔓 | 受击解锁，原动物保留；同一回合不重复消除刚解锁动物 |
| 冰块 | 按层数受击；目标进度按实际破除层数结算 |
| 死局 | 只计算能由交换形成的匹配；洗牌后无现成匹配且至少有一步有效移动 |
| 周期受伤 | 每完成配置的 `dangerInterval` 次有效行动，若目标未达成则受到 `damagePerTick` 点伤害；血量为零才失败 |

特殊动物组合建立显式矩阵，不用分支尾部的“兜底效果”：方向×方向、方向×爆炸、爆炸×爆炸、彩鸟×普通、彩鸟×方向、彩鸟×爆炸、彩鸟×彩鸟。每项明确受击范围、障碍吸收、连锁顺序和计分。特殊动物仍保留其动物种类；单个特殊动物需要同类匹配才触发。

### 2. 配置化关卡

新增版本化 `LevelConfig`（JSON 或 Cocos 资源）：`id`、棋盘宽高和可用格、动物池、初始布局、生成器、**单个** `target`、`maxHealth`、`dangerInterval`、`damagePerTick`、障碍数组、`ruleIds`、星级阈值、难度标签、教学触发。目标类型先支持指定动物数量、清除冰块或藤蔓；后续可增加收集物落底。分数保留为表现与评价指标，不作为首版关卡胜利目标。

校验器拒绝非法坐标、重叠冲突、无效目标、非正生命/伤害间隔、开局现成消除和无合法移动。关卡编辑先采用可读 JSON 与预览工具，再决定是否需要专门可视化编辑器。`ruleIds` 只引用经过兼容性校验的规则；规则效果按稳定顺序执行，为未来遗物留统一接口。

### 3. 血条压力与可组合规则

`HealthPressure` 独立于棋盘，保存当前血量、最大血量、距下一次受伤的有效行动数和护盾。默认参数建议从 `5 HP / 每 4 次有效行动受 1 点伤害` 开始试玩调优；它是配置初值，不是硬编码限制。一次无效交换、连锁、动画或自动洗牌均不增加危险值。治疗不超过最大血量，护盾和减伤有上限，避免规则叠加导致永久无敌。

规则游玩集提供基础、逐渐加速、连击防护、目标奖励、玻璃心等变体；每关仍只有一个主要目标。每个变体声明修改的时机、数值上限、与其他变体的兼容性和 HUD 提示。遗物将来复用相同的事件与效果系统，但属于玩家持有的跨关卡或局内状态，而关卡规则由关卡配置决定。细节见 [规则游玩集](GAMEPLAY_RULESET.md)。

### 4. 表现、资源和性能

- `GameManager.ts` 逐步拆为会话协调、棋盘视图、障碍视图、HUD、关卡流程；`TileItem` 只负责显示与输入反馈。
- 资源加载改用 Cocos 资源目录或 Asset Bundle，逐步移除 `VisualAssets.ts` 中内嵌的 Base64 图片；保留现有原创动物图与完整特殊状态图。
- 动画以规则事件驱动：交换、命中、藤蔓断裂、动物消失、下落、目标进度、危险预警、受伤和胜负结算有统一时序，允许跳过长动画但不跳过结算。
- 目标设备上维持 60 FPS；一次大范围连锁的可见反馈在约 1 秒内进入下一次可操作状态。性能门槛以实测确定，先建立帧耗时和内存基线。
- 支持常见竖屏比例、触控热区、静音、低运动效果和可辨色的动物轮廓。

### 5. 进度与质量体系

- 本地存档：已解锁关卡、每关最高星级、设置和当前关卡检查点；带版本号和迁移函数，写入采用临时记录加校验，避免损坏主档。
- 规则测试：固定局面表、特殊组合矩阵、障碍交互矩阵、血条边界、规则/遗物触发顺序和种子回放；随机棋盘属性测试检查无丢块、无重复消除、落点合法、伤害不重复。
- 关卡测试：每关首局可行动、单一目标可达、关键教学可触发；记录试玩的通过率、达成目标所需行动数、受伤次数、胜利剩余血量与失败原因，按小样本调参。
- 发布门槛：Cocos 3.8.x 编辑器预览、移动端真机操作、存档升级、连续 30 局无卡死、异常种子可回放。当前仓库无 Cocos 编辑器自动化环境，需补齐本地构建/预览流程。

## 阶段顺序

1. **规则可信**：状态机、种子、规则矩阵、藤蔓与五连回归，消除无死循环。
2. **关卡可玩**：单目标配置、血条与受伤预告、胜负与重试、前 10 关教学曲线。
3. **内容可扩**：30 关、规则游玩集、更多障碍、关卡校验与数据调优。
4. **体验成熟**：地图/星级/存档、音画与移动端性能、可访问性。
5. **持续更新**：活动和新增玩法建立在可验证的关卡管线之上；不把“关卡数量”当首版质量指标。

## v1.0 之后的长期系统

当单机主线通过留存试玩和内容生产验证后，再分独立里程碑规划：

| 方向 | 最小可验证版本 | 技术前置 |
| --- | --- | --- |
| 遗物与局内构筑 | 从少量遗物中选择并装备，改变治疗、护盾、危险值或目标推进 | 统一事件钩子、触发顺序、叠加上限和存档版本 |
| 道具与库存 | 局前选择治疗、护盾、锤子、强制交换等有限道具；明确获得与消耗记录 | 可回放的规则事件、存档版本与防重复扣除 |
| 日常/限时活动 | 使用现有关卡配置定义每日挑战和周期目标 | 内容版本、时间窗口与离线时钟处理 |
| 社交与排行榜 | 先做可选的好友成绩展示，再评估实时排行 | 账号、服务端校验、隐私与反作弊设计 |
| 跨设备进度 | 本地存档与账号同步，冲突时可解释地合并 | 账号体系、存档版本与服务端存储 |
| 商业化 | 仅在核心体验成熟后评估；道具收益不能破坏关卡公平性 | 支付平台、未成年人保护、透明提示与合规评审 |

这些系统可以向参考产品学习“持续有新目标”的节奏，但具体数值、美术与活动内容应由本项目试玩数据和原创设计决定。
